1""" 

2Process-wide serialisation of PortAudio stream lifecycle calls. 

3 

4PortAudio explicitly documents opening and closing streams as NOT thread 

5safe (https://github.com/PortAudio/portaudio/wiki/Tips_Threading), and its 

6Windows host APIs abort the whole process on internal assertion failures. 

7Jarvis touches PortAudio from several independent threads — the voice 

8listener's run loop, the Windows mic-permission check thread, the dictation 

9engine's worker threads, the TTS playback thread, and the thinking-tune 

10player. Unserialised open/start/stop/close/abort calls across those threads 

11are the root cause of the Windows "Fatal Python error: Aborted" crash 

12family (#462, #401, #422). 

13 

14Every stream lifecycle call (constructing an ``InputStream``/``OutputStream`` 

15and calling ``start``/``stop``/``close``/``abort`` on it, plus blocking 

16``sd.play`` which opens a stream internally) must run inside 

17``portaudio_lock``. Do NOT hold the lock across playback waits or other 

18blocking work, and never acquire another lock while holding it — take it 

19innermost, around the direct sounddevice call only. 

20 

21Accepted exceptions: 

22- The dictation beep holds the lock across its blocking ``sd.play`` — 

23 sub-200ms, and splitting play/wait would leave the internal stream's 

24 teardown unguarded. 

25- The Windows mic-permission probe opens its stream WITHOUT the lock: that 

26 open can hang indefinitely when Windows blocks mic access, and hanging 

27 while holding this lock would freeze every audio user in the process. 

28""" 

29 

30import threading 

31 

32# Re-entrant so a guarded close inside a guarded open-fallback path is safe. 

33portaudio_lock = threading.RLock()
