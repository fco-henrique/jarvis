1"""The two-tier model system. 

2 

3Jarvis runs every LLM context on one of two models: 

4 

5- ``Tier.FAST`` — the small, warm, low-latency model behind real-time 

6 classification passes. These contexts take a few thousand tokens in and 

7 emit tiny strict-JSON answers, so latency dominates and a ~2B model is 

8 ideal. 

9- ``Tier.CHAT`` — the capable model that writes replies, plans, 

10 summarises, and extracts knowledge. Long-form output; quality dominates. 

11 

12The Model tiers table in ``llm.spec.md`` is the authoritative list of 

13which context runs on which tier; docstrings elsewhere point here rather 

14than re-enumerating it. 

15 

16Both fields are fully resolved at config load (``fast_model`` / 

17``llm_chat_model`` always hold a provider-valid model name), so resolution 

18here is a plain field read. Keeping it behind one function means every 

19context states its tier instead of inventing a fallback chain, and any 

20future routing logic lands in exactly one place. 

21""" 

22 

23from __future__ import annotations 

24 

25from enum import Enum 

26 

27 

28class Tier(Enum): 

29 """Which of the two models a context runs on.""" 

30 

31 FAST = "fast" 

32 CHAT = "chat" 

33 

34 

35def resolve_model(cfg, tier: Tier) -> str: 

36 """Return the model name for ``tier`` under the active settings. 

37 

38 ``Tier.FAST`` reads ``cfg.fast_model``; ``Tier.CHAT`` reads 

39 ``cfg.llm_chat_model``. An empty fast model (possible only on 

40 hand-built cfg objects — config load always resolves it) falls back 

41 to the chat model so a context never receives an empty name. 

42 """ 

43 chat = str(getattr(cfg, "llm_chat_model", "") or "").strip() 

44 if tier is Tier.FAST: 

45 return str(getattr(cfg, "fast_model", "") or "").strip() or chat 

46 return chat
